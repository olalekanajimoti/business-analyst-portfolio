## Standard artefact pack

Every project folder follows the same structure, so a reviewer can compare cases quickly. Test status is shown honestly: Passed or Released (live in the product) for delivered work, Planned for products in development or concept, and illustrative for generalised analysis.

| Folder | Included evidence |
|---|---|
| `Data/` | An anonymised data dictionary and evidence-handling note |
| `Deck/` | A concise executive PDF covering the problem, objectives, analysis and evidence |
| `Diagrams/` | As-Is and To-Be swimlanes, gap analysis and a layered solution overview (SVG and PNG) |
| `Docs/` | BRD, FRD, traceability matrix, UAT plan, stakeholder and communications plans, MoSCoW and data dictionary |
| `Excel/` | Workbook linking objectives, requirements, functional requirements, stories, RAID, UAT and traceability, with formula-driven counts |
| `Dashboard/` | Evidence overview: requirements by priority, tests by status and risks by severity |

The artefacts are tailored to each case rather than duplicated as generic templates. Product concepts are clearly separated from delivered work, and confidential datasets are not represented as public evidence.

## Portfolio integrity

The case studies are reconstructed from genuine work and product-development experience. Commercially sensitive information, personal data and confidential operational details have been removed or generalised. Where original datasets cannot be published, the repository explains the evidence used without presenting synthetic information as original client data.

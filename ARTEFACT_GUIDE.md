# Artefact Guide

Each flagship case study follows a consistent evidence structure.

| Artefact | Purpose |
|---|---|
| Project README | Executive overview of the problem, approach, contribution and outcome |
| BRD and FRD | Objectives, scope, business and functional requirements, rules, user stories and risks |
| Process maps | As-Is and To-Be swimlanes with start and end events, labelled decisions and highlighted pain points |
| Requirements traceability | Link between business need, requirement, acceptance criterion and validation |
| UAT evidence | Test scenarios, expected results and status |
| KPI framework | Measures used to evaluate adoption, service quality or business value |

## Status labels

- **Delivered:** implemented work supported by genuine project experience.
- **In development:** actively designed or being built, with requirements subject to refinement.
- **Concept/MVP:** structured product analysis showing discovery and proposed scope; not represented as fully deployed.

## Reading the evidence

The most useful sequence is:

1. Read the project README.
2. Review the business analysis pack.
3. Inspect the process model.
4. Review requirements and tests.
5. Examine outcomes and lessons learned.
